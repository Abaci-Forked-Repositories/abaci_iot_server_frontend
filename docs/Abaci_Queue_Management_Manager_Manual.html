1. Introduction and recommended order

This manual explains how the system is set up and used, in the same order you should work in real life. You do not need deep technical knowledge. Each section lists the create/edit screens (modals) and what each field means. Empty boxes are left for screenshots you can paste later.

After login
You land on the Dashboard — use it to see how the system is running before you go into setup or daily work.

Recommended setup order

1. Create Serving Points (counters)
2. Create a Queue and attach serving points to it
3. Open the queue and create a Schedule (time window)
4. Inside the schedule, create Tokens for customers
5. Staff at a serving window start serving — the system then assigns the token to that counter
6. Create Templates (how the TV looks)
7. Create Screens, assign templates, open the public display
8. Add staff in User Management and configure Settings
Important (checked in the frontend):
• When you create a token, the frontend does not pick a serving point. Serving points are only shown as a read-only list. The backend assigns a token to a counter when staff clicks Start serving on a serving window.
• When you create a token, the frontend sends customer details (name, email, phone, and so on) to the token-create API. It does not call a separate “create token user” API. The backend creates or links the token user from those fields.

6.2 How a token user is created

The frontend sends one request: create token, with customer fields (name, email, phone, age, place, remarks) plus schedule and token number.
There is no separate “create token user” button in this flow. The backend creates or reuses a token user from those fields and attaches it to the token.
Later you can view people under Token Users and edit their details. That is viewing/updating, not the original create step.
Screenshot: Token Users list / Token User detail

Paste image here later

6.3 How a token is assigned to a serving point

The frontend does not assign a serving point when the token is created.
Assignment happens when staff on a serving window clicks Start serving. The frontend calls the serving-window “start serving” API. The backend picks the next waiting token and links it to that counter.

7.2 Actions on the serving window

These buttons send requests to the backend. The frontend does not invent the next token assignment itself.

ActionWhat happens
Start servingBackend assigns the next waiting token to this window and marks it as serving.
CompleteService finished. If a next queue is set, the backend can create a token there. You may choose a next queue and optionally set the counter status.
CancelToken cancelled. Optional: set counter status at the same time.
No showCustomer missed the call. Optional: set counter status.
PostponeOnly if postpone is allowed. Backend issues a new token; a popup can show the new number.
SkipSkip the current token (window skip API), with optional counter status.

7.3 Token status from Token Users

On a token user’s detail page, staff with permission can change some statuses:

  • From Registered → Waiting, Cancelled, or Postponed
  • From Waiting → Cancelled or Postponed

These call token APIs (cancel / postpone / mark waiting). Serving and complete still happen at the serving window.

Typical zone editing:

  • Draw or place a zone on the canvas.
  • Drag to move; resize from the edges.
  • Select a zone to open Zone properties.
  • Set appearance: solid fill colour, or a display theme (designed token look).
  • Set opacity so the zone can sit over a background image.

9.3 Multiple queues on one zone

In zone properties, Queues is a multi-select. Assign one queue, or several queues, to the same zone.

  • One queue — the zone shows that queue’s current token and related info.
  • Several queues — the zone can show more than one line. If the chosen theme supports it, you get Display mode.

9.4 Display mode

Display mode appears when:

  • the zone uses a theme that supports a multi-queue table, and
  • more than one queue is assigned to that zone.
ModeWhat the visitor sees
SingularOne combined / rotating view rather than a full table.
TabularA table/board listing multiple queues (live multi-queue board).
